# Sidebar

상단 워크스페이스 탭에 열린 페인과 배치를 묶는 BB 플러그인이다. 왼쪽 리본 메뉴와 스레드 목록은 BB가 제공하는 것을 그대로 사용한다.

## 동작

워크스페이스 탭·배치 복원·열기 방식·새 여백 스타일은 `useDeviceChrome()`의 `device === "desktop"`일 때만 적용한다. phone과 tablet에서는 워크스페이스 저장소와 내비게이션을 변경하지 않는다. 좁힌 데스크톱 창은 계속 데스크톱으로 처리한다.

- 처음에는 `기본` 탭 하나가 있다. `＋`는 비어 있는 워크스페이스를 추가한다.
- 탭은 같은 너비의 테두리 안에 제목과 닫기 버튼을 함께 둔다. 긴 제목은 줄임표로 표시하고 포인터를 올리면 전체 제목을 보여 준다.
- 각 워크스페이스는 화면 경로, BB의 네이티브 페인 트리, 분할 크기, 활성 페인과 최대화 상태를 기억한다.
- 마지막 워크스페이스는 닫을 수 없다. 페인을 닫는 것과 워크스페이스를 닫는 것은 별개다.
- 왼쪽 리본 메뉴와 스레드 목록에서 화면을 열면 `openMode`에 따라 새 페인에 추가하거나 활성 페인의 내용을 교체한다.
- 좌우 사이드바는 공통 셸이다. 워크스페이스별 별도 도구 목록을 만들지 않는다.
- 데스크톱은 사이드바와 각 페인 사이를 여백과 둥근 모서리로 구분한다. 이전 `desktopLayout` 토글은 제거했다.
- 각 페인과 우측 패널은 헤더·본문의 바깥 배경을 투명하게 하고, 뒤에 `--sidebar` 색의 18px 둥근 배경을 둔다. 입력창·카드·선택 항목과 비활성 페인의 포커스 음영은 유지한다.
- 활성 페인은 제목에 배경을 칠하는 대신 테마의 `--ring` 색으로 얇은 테두리와 은은한 빛 번짐을 표시한다. 강조는 220ms 동안 나타나고 사라지며, `prefers-reduced-motion`에서는 즉시 바뀐다.
- 페인 제목을 끌어 실제 드래그가 시작되면 현재 페인과 우측 패널의 내용을 잠시 가린다. 스레드는 선택한 프로바이더 아이콘과 제목을 가운데 표시하며 긴 제목은 두 줄로 줄인다. 프로바이더 정보를 아직 읽을 수 없으면 말풍선을 사용한다. 플러그인은 헤더의 아이콘을 사용한다. 원래 콘텐츠 DOM과 드롭 영역은 유지하며 드롭·Esc·취소·창 포커스 이탈 시 다시 보여 준다.
- 페인 영역은 사이드바의 위·아래 끝선에 맞춘다. 좌우 사이드바와 페인 사이는 기존 페인 간격과 같은 9px(양쪽 4px 여백과 1px 경계)이며, 왼쪽 콘텐츠 폭은 여백을 뺀 실제 사이드바 폭 안에 둔다.
- 창 오른쪽·아래쪽에는 기존 페인 여백에 4px를 더해 약 8px의 바깥 간격을 둔다. 왼쪽 사이드바의 아래 여백도 8px로 맞추며, 왼쪽·상단의 위치와 페인 사이 간격은 유지한다.
- 데스크톱의 좌우 사이드바 열기·닫기와 페인 확장·복원은 즉시 전환한다. 폭을 매 프레임 바꾸는 전환을 없애고, phone용 위치 추적·밝기 필터를 데스크톱에 설치하지 않는다. 콘텐츠 내부 버튼의 효과와 phone 모션은 유지한다.
- 기존 phone 드로어·shelf 모션과 햅틱은 유지한다. 기기 판정 원본인 `lib/device.ts`, `lib/use-device.ts`는 수정하지 않는다.

## 설정

설정의 Sidebar에서 「스레드·플러그인 페이지를 열 때」를 선택한다.

| 값 | 화면 표시 | 기본값 |
| --- | --- | --- |
| `new-pane` | 새 페인에 열기 | 기본 |
| `replace` | 현재 활성 페인의 화면 교체 | — |

CLI에서도 바꿀 수 있다.

```sh
bb plugin config sidebar set openMode new-pane
bb plugin config sidebar set openMode replace
```

## 복원 경계

현재 BB SDK에는 전체 페인 배치를 복원하는 공개 API가 없다. 이 구현은 BB 소스에서 확인한 `bb.splitLayout`의 version 1 세션 저장 형식을 사용하며, 저장소가 지원하는 범위에서 화면을 다시 불러와 복원한다. BB 앱 소스나 설치 파일은 수정하지 않는다.

왼쪽 리본·스레드 목록·새 스레드 버튼은 BB의 네이티브 분할 열기를 사용하므로 화면을 재로드하지 않는다. 이미 열린 화면은 해당 페인에 포커스를 옮긴다. 교체 모드는 일반 내비게이션을 그대로 사용한다. BB가 분할을 지원하지 않는 좁은 창에서는 네이티브 일반 열기를 따른다.

첫 1→2 분할에서는 BB가 단일 페인과 분할 트리를 다르게 렌더하므로 채팅 컴포넌트가 다시 마운트된다. 플러그인의 전체 문서 재로드는 제거했지만, BB 내부의 이 마운트 전환까지 없애지는 않는다.

워크스페이스 탭 추가·전환·활성 탭 닫기는 아직 앱 화면 재초기화를 수반한다. 서버의 에이전트 실행은 중단하지 않는다. 워크스페이스 목록은 창의 `sessionStorage`에 두므로 같은 창의 재로드에서는 유지되고 새 앱 세션에서는 기본 탭으로 시작한다. 플러그인 내부의 메모리 상태와 네이티브 Browser·Terminal 뷰를 그대로 마운트해 유지하는 것은 보장하지 않는다.

BB의 최대 8개 페인 제한을 따른다. 새 페인 모드에서 한도를 넘기면 기존 페인을 임의로 교체하지 않고 안내한다. 손상된 저장값은 기본 워크스페이스로 되돌린다.

## 확인

```sh
npm test
npm run typecheck
bb plugin build .
bb plugin reload sidebar
```

화면의 최종 판정은 사용자가 한다. `bb plugin list --json`의 설치 경로와 번들 해시를 함께 확인한다.

## 설치

```sh
bb plugin install path:/Users/kebab/Foundry/bb-plugin/bb-plugin-sidebar --yes
```

plugin id는 `sidebar`다. `plugin:sidebar:chat-canvas`는 별도로 선택할 수 있는 채팅·사이드바 테마다. 다른 BB 테마의 팔레트를 덮어쓰지 않는다.
